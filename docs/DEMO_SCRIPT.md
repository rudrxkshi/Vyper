# SIH demonstration script (5–7 minutes)

## 0:00–0:40 — Problem

Explain that reuse and recycling require defensible media-sanitization records. VYPER selects capability-appropriate methods, verifies only what the method can support, and reports uncertain outcomes as `INCONCLUSIVE`.

## 0:40–1:15 — Download and local console

Open the central download page, show Linux x86_64 availability and SHA-256 metadata, then show the installed loopback-only console. Mention that Windows/macOS packages and signed releases are not yet available.

## 1:15–2:00 — Discovery and safety

Show the disposable 5 GiB VirtualBox disk and the protected system disk. Highlight model, serial, capacity, mounts, and system-device classification. Explain that the browser has no arbitrary root-command endpoint.

## 2:00–3:15 — Policy and execution

Select the disposable HDD-like VDI. Show `HDD_OVERWRITE`, explicit authorization, and measured byte progress. Explain that ATA and NVMe firmware operations remain indeterminate unless trustworthy protocol progress exists.

## 3:15–4:10 — Verification and evidence

Show terminal `VERIFIED`, representative sample verification, evidence SHA-256, and the certificate. State precisely: this is evidence-backed, method-specific verification; it is not a guarantee about every hidden or remapped physical location.

## 4:10–4:50 — Central dashboard

Show outbound-only agent synchronization, matching target identity, lifecycle events, certificate, and tamper-evident audit-chain fields. Mention that a remote destructive request still requires local approval.

## 4:50–5:50 — No-USB system-disk workflow

Show the dry-run `vyper system-disk prepare` output, authenticated expiring manifest, one-shot GRUB entry, identity revalidation, and fresh boot-console confirmation. Label the terminal fixture result as dry-run/mocked unless performed later on approved disposable hardware.

## 5:50–6:30 — Sustainability value

Connect trustworthy disposition records to safer device reuse, donation, refurbishment, and circular-economy workflows. Close with the honest readiness statement: ready for demonstration and controlled disposable-hardware validation, not production-ready and not yet physically validated across the hardware matrix.
